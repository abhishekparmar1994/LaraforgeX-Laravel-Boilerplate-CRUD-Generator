LaraforgeX

A clean, headless backend starter template for Laravel 13. Built specifically to help developers write highly structured, secure, and scalable systems like SaaS, ERP, CRM, and LMS portals.

Get Started Try API Sandbox

Grouped by Features

We group files by features (like Users or Billing) instead of file types. This keeps your code organized, easy to find, and easy to edit.

Enhanced Auth Security

Includes simple Google Authenticator 2FA, passwordless email login links, and automatic role inheritance (like Admin inheriting Teacher permissions).

Direct-to-Cloud Uploads

Upload files directly from the browser to Amazon S3 or Cloudflare R2. This saves server memory, bandwidth, and prevents slow page speeds.

Installation & Sandbox Setup

Run the project locally on your machine.

LaraforgeX requires PHP 8.3+ and Composer 2.0+. Make sure your local database (MySQL/PostgreSQL) and Redis are running.

Terminal Commands
# Navigate to the Laravel API Core folder
cd apps/api

# Copy environment configuration and generate app key
cp .env.example .env
php artisan key:generate

# Run database migrations and seed sandbox data
php artisan migrate:fresh --seed
Sandbox Data Loaded: Running the seeder creates three standard test accounts (Admin, Teacher, and Student) with pre-configured UUIDs matching our API sandbox simulator below.

Feature-Based Directory Structure

Grouping files by features instead of file types.

Standard Laravel projects mix all controllers, models, and requests together. In big projects, finding your files gets hard. LaraforgeX fixes this by grouping all files for a single feature (like Users, Settings, or Media) inside a single directory under `app/Domains/`.

  • Actions: Classes that do exactly one task (e.g., CreateUserAction).
  • DTOs (Data Transfer Objects): Clean, read-only parameters lists that validate input data.
  • Repositories: Classes that handle all database queries.
  • Providers: Autoload file routing and dependencies bindings automatically.
Directory Layout
app/Domains/User/
├── Actions/ # Handles workflow logic
├── DTOs/ # Typed request parameters
├── Models/ # Database UUID models
├── Policies/ # Route gate rules
├── Requests/ # Form validations
├── Resources/ # Outbound API formatters
├── Repositories/
├── Contracts/ # Repository interfaces
└── Eloquent/ # Database query code
├── Enums/ # Domain status values
├── Events/ # Dispatched core events
├── Listeners/ # Event callback triggers
├── Notifications/ # System mail/alert classes
├── Jobs/ # Queued background tasks
├── Exceptions/ # Custom error exceptions
├── Traits/ # Shared helper functions
├── Rules/ # Custom validation rules
├── Interfaces/ # Custom code contracts
├── Tests/ # Unit & feature tests
└── UserServiceProvider.php

Artisan Domain Generator

Create new feature folders and boilerplates in one click.

Instead of creating folders, files, and binding service providers manually, you can use our simple custom generator command:

Artisan CLI
php artisan make:domain Billing

This command instantly scaffolds a new folder under `app/Domains/Billing/` along with the matching `BillingServiceProvider`, base Eloquent models, repository templates, validation requests, JSON resource formatters, and test suites.

Clean Code Patterns

Visualizing files inside a feature flow.

Each class has one clean task. Here is how a business workflow (like creating a user) is structured across files: 

<?php

declare(strict_types=1);

namespace App\Domains\User\Actions;

use App\Domains\User\DTOs\CreateUserDTO;
use App\Domains\User\Models\User;
use App\Domains\User\Repositories\Contracts\UserRepositoryInterface;
use Illuminate\Support\Facades\Hash;

class CreateUserAction
{
    public function __construct(
        protected UserRepositoryInterface $repository
    ) {}

    public function execute(CreateUserDTO $dto): User
    {
        $userData = [
            'name' => $dto->name,
            'email' => $dto->email,
            'password' => Hash::make($dto->password),
            'status' => $dto->status,
        ];

        /** @var User $user */
        $user = $this->repository->create($userData);

        if (!empty($dto->roles)) {
            $user->assignRole($dto->roles);
        }

        return $user;
    }
}
<?php

declare(strict_types=1);

namespace App\Domains\User\DTOs;

use App\Shared\DTOs\BaseDTO;

class CreateUserDTO extends BaseDTO
{
    public function __construct(
        public readonly string $name,
        public readonly string $email,
        public readonly string $password,
        public readonly string $status = 'active',
        public readonly ?array $roles = null
    ) {}
}
<?php

declare(strict_types=1);

namespace App\Domains\User\Repositories\Eloquent;

use App\Domains\User\Models\User;
use App\Domains\User\Repositories\Contracts\UserRepositoryInterface;
use App\Shared\Services\BaseRepository;

class UserRepository extends BaseRepository implements UserRepositoryInterface
{
    protected function model(): string
    {
        return User::class;
    }

    public function findActiveByEmail(string $email): ?User
    {
        return $this->model->newQuery()
            ->where('email', $email)
            ->where('status', 'active')
            ->first();
    }
}
<?php

declare(strict_types=1);

namespace App\Domains\User\Controllers;

use App\Domains\User\Actions\CreateUserAction;
use App\Domains\User\DTOs\CreateUserDTO;
use App\Domains\User\Requests\CreateUserRequest;
use App\Domains\User\Resources\UserResource;
use App\Http\Controllers\Controller;
use Illuminate\Http\JsonResponse;

class UserController extends Controller
{
    public function store(CreateUserRequest $request, CreateUserAction $action): JsonResponse
    {
        // Requests validated by validation middleware. Map to DTO.
        $dto = CreateUserDTO::fromRequest($request);

        $user = $action->execute($dto);

        return response()->json([
            'success' => true,
            'message' => 'User created successfully.',
            'data' => new UserResource($user)
        ], 201);
    }
}

Roles & Auth Security

Security setups and permission workflows explained simply.

1. Role Inheritance (Hierarchical RBAC)

Roles can inherit permissions from other roles using a parent-child relationship. We use a simple parent_id logic:

Role: administrator (parent_id: null)
└── Role: educator (parent_id: administrator_uuid)
    └── Role: student (parent_id: educator_uuid)

Instead of assigning the same permissions multiple times, parent roles automatically get permissions of child roles. For example, the administrator automatically gets all permissions of educator and student.

2. Secure Google 2FA

Secure login using Google Authenticator codes. It works out-of-the-box without using heavy external packages. Users scan a QR code and type a 6-digit confirmation code. We also generate encrypted single-use codes for account recovery.

3. Passwordless Magic Links

Send secure timed login links directly to user emails. Tokens are securely hashed with SHA256 before being saved, keeping accounts safe even if database records are compromised.

How to Sync Roles and Permissions

A. Update Database Roles (Code to DB)

Permissions and role structures are managed inside database/seeders/DatabaseSeeder.php.

  1. Add or edit permission names inside the array.
  2. Map permission lists to specific roles.
  3. Update roles using: php artisan db:seed

B. Sync Frontend Models (API to Frontend)

Keep your frontend portals aligned with API models and role specifications instantly:

  1. Make schema changes in your migrations or models.
  2. Compile configurations using: php artisan typescript:transform
  3. Nuxt portals automatically pull these schemas from shared/types/.
Two-Factor Authentication (2FA) Integration Guide

1. Request 2FA Setup (API Endpoint)

The user requests to set up 2FA. This returns a raw secret key and a formatted QR-code URI string: 

// Request 2FA setup details (Headers must contain Bearer Token)
const response = await fetch('/api/v1/auth/2fa/enable', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ...', 'Accept': 'application/json' }
});

const { data } = await response.json();
// data.secret: "KJSW23MNS76AX29S"
// data.qr_code_url: "otpauth://totp/LaraforgeX:user@example.com?secret=KJSW23..."

Display the QR-code on the client frontend using a JS QR builder (e.g. qrcode.js) so the user can scan it in Google Authenticator.

2. Confirm 2FA Verification Code

Prompt the user to enter the 6-digit code displayed in their authenticator app and post it to verify: 

// Verify the 6-digit TOTP code
const response = await fetch('/api/v1/auth/2fa/verify', {
  method: 'POST',
  headers: { 
    'Content-Type': 'application/json',
    'Authorization': 'Bearer ...',
    'Accept': 'application/json'
  },
  body: JSON.stringify({ code: '482931' }) // 6-digit user input code
});

const result = await response.json();
if (result.success) {
  // result.data.recovery_codes contains 8 backup recovery codes
  console.log("Two factor enabled successfully!", result.data.recovery_codes);
}

Encrypted Settings Store

Transparent encryption for sensitive platform credentials.

Sensitive configurations (like SMTP passwords and API tokens) are saved under `settings`. When a setting is updated with is_encrypted = true, it is encrypted automatically before writing to the database, and decrypted automatically when queried.

# Saved in Database:
key: "mail_password" | value: "eyJpdiI6Ik9zSmxSR..." | is_encrypted: true

# Loaded in Code:
$settingsRepository->get('mail_password'); // Output: "VerySecretSmtpPassword123!"

Cloud Media Manager

Upload big files directly to AWS S3, GCP, or Cloudflare R2.

Normally, uploading files directly to your server slows down pages. LaraforgeX uploads files directly from the browser to AWS S3, Google Cloud Storage (GCP), or Cloudflare R2 using temporary secure links, bypassing web server upload limits.

Step 1
Request Presigned URL

Browser requests an upload link from the API with size and type metadata.

Step 2
Browser Binary Push

Browser uploads the file directly to S3/GCP/R2 storage container.

Step 3
Confirm Upload

API confirms the file upload is complete and generates temporary preview URLs.

Media Integration Code Guide

1. Uploading a File (Frontend JavaScript)

First, request a presigned URL from the API, then upload the file binary directly using a PUT request: 

// Step A: Request the presigned URL
const response = await fetch('/api/v1/media/presign', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer ...' },
  body: JSON.stringify({ name: 'file.mp4', mime_type: 'video/mp4', size: 1024 })
});
const { data } = await response.json();

// Step B: Upload file binary directly to S3 / GCP / R2
await fetch(data.upload_url, {
  method: 'PUT',
  headers: { 'Content-Type': 'video/mp4' },
  body: fileObject // Raw File object from input
});

// Step C: Confirm completion to API
await fetch(`/api/v1/media/${data.media.id}/confirm`, {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ...' }
});

2. Accessing Files (Backend PHP Code)

To read the files or generate secure temporary signed URLs in your PHP controllers or resources: 

use App\Domains\Media\Models\Media;

// Find media file record by UUID
$media = Media::findOrFail($uuid);

// A. Get full public download URL (if disk visibility is set to public)
$url = $media->getUrl(); 
// Output: "https://your-bucket.s3.amazonaws.com/media/user_id/..."

// B. Get secure temporary download link (if disk visibility is private)
$temporaryUrl = $media->getTemporaryUrl(now()->addHour());
// Output: "https://your-bucket.s3.amazonaws.com/media/...&X-Amz-Signature=..."

Queued Audit Trails

Track database changes automatically in the background.

Track edits to your models (created, updated, deleted) automatically. It logs what values changed, when, and who performed the change. The logging task runs in the background using worker queues so it does not slow down API responses.

# User update event detected
WriteAuditLogJob::dispatch($auditData); // Dispatched to background Redis queue
